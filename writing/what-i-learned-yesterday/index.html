What I learned Yesterday

March 12, 2026 · originally on substack

Some heuristics to get better at writing clean code that cam approves of:

  • network calls are slow, and you should parallelize them. I lowkey knew this but still had this as a nit in a pr. NTS: whenever making api requests in my code make sure they are implemented efficiently during pr review.

  • Minimize parameters whenever you can. Aggressively cut complexity out of your code. If you aren’t adding things back in at least 20% of the time, I think you might not be trying hard enough to cut the complexity.

  • Probably better to use public APIs for grabbing properties and such instead of calling some private attributes of the object because its much more likely some attribute will change and you have a weird bug that is probably going to cause u pain.

  • Retry’s are important, but I knew this. What I learned is to be careful of non idempotent actions when implementing retrys. It is very easy to just be like “retry if timeout” but its possible some sub tasks of your action were executed on the server and retrying fucks something up because it takes a different path on the server.

Some stuff i learned about how actions work on the backend:

  • function sdk client does NOT have access to the action endpoint, but CM sdk client does. Also, action edits are always compiled as a json and then applied to the ontology at the END. There are many down stream effects of this that u can think about. Note: tsv1 is apparently not a global client and some other dark magic, but nonetheless, the token that is like abstracted away from you does not have access to the actions api

  • The way around above is to create your own token with special perms and the only way to do this in foundry is with a service user. This however makes it so actions are really executed by the client and not the user clicking the button which maybe is bad for security.

  • I wish they had the ability to define as many transactions as you want in functions. that would solve all my problems :(
